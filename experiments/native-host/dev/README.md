# Native host development supervisor

This isolated, dependency-free Rust executable supervises one persistent Rolldown
watcher. It publishes complete immutable revisions, preserves earlier successful
artifacts when compilation fails, and optionally runs an explicitly selected
deployment adapter. It does not rebuild native code automatically. Native build
scripts remain separate from this JavaScript development loop.

From `experiments/native-host`:

```sh
cargo run --manifest-path dev/Cargo.toml -- --help
cargo run --manifest-path dev/Cargo.toml --
```

Type `quit` followed by Enter, or send SIGINT/SIGTERM, to close the watcher and
terminate an active deployment. On Unix, each child gets its own process group;
shutdown sends graceful stop first, then escalates after two seconds. Killing the
supervisor with SIGKILL cannot run cleanup. The supported development hosts for
this prototype are macOS/Linux; Windows descendant-process cleanup is not proven.

The CLI accepts `--root PATH`, `--entry js/entry.jsx`, `--build-delay MS` (0–10000),
`--node PATH`, and `--watch-script PATH`. The last option supports protocol tests.
It defaults to the real watcher beside this crate, even with a fixture `--root`.

To opt into an adapter, supply `--deploy-command EXECUTABLE` and zero or more
`--deploy-arg VALUE` arguments. Arguments are passed directly without a shell. The
supervisor appends the exact revision directory as the final argument and sets
`NH_DEV_REVISION` and `NH_DEV_REVISION_DIR`. No platform action happens without this
option. Deployment stdout is recorded in `build/dev-logs/<revision>.log` and stderr
remains visible. Completion means the adapter process exited successfully; it does
not establish that a native frame was displayed. A failed deployment is reported
without deleting the artifact. While one deployment runs, newer revisions replace
one pending slot, so only the latest pending revision is deployed next.

## Artifact and reload contract

Successful builds publish this directory with a single atomic rename:

```text
build/revisions/<decimal revision>/
  app.bundle.js
  app.bundle.js.map
  manifest.json
```

The revision identifier is a **string**, not a JavaScript number: a millisecond
timestamp, a random 64-bit decimal session nonce and an eight-digit sequence.
Session nonces avoid collisions across watcher restarts/concurrent sessions;
publication refuses existing nonempty directories. Order is guaranteed within
one watcher session; identifiers are not a cross-process ordering protocol.

The manifest contains:

```json
{
  "schemaVersion": 1,
  "revision": "<decimal string>",
  "sha256": "<lowercase SHA256 of app.bundle.js>",
  "byteLength": 123,
  "sourceMap": {
    "file": "app.bundle.js.map",
    "sha256": "<lowercase SHA256 of source map>",
    "byteLength": 456
  },
  "createdAt": "<ISO timestamp>",
  "mode": "development",
  "reload": "full",
  "buildDurationMs": 1
}
```

The watcher captures both files synchronously in Rolldown's `writeBundle` hook,
then writes and renames the revision synchronously before announcing it. A later
build cannot overwrite half of a captured pair or publish ahead of an earlier
revision. Source maps retain the same relative directory depth as staging.
Failed transforms emit `bundle.failed`, publish nothing, and leave all successful
directories intact. There is no mutable `latest` pointer. Old revisions and logs
are retained until explicitly removed while the supervisor is stopped.

Native adapters must stage an exact directory into the app sandbox and validate
the manifest revision, byte length and SHA256 independently before execution.
Reload destroys/recreates the native runtime or process. React state, pending
service work and WebView history reset: **this is full reload, not HMR or React
Refresh**. In-process reload and state preservation are separate future work.

## Events, limits and measurement

Supervisor stdout is NDJSON. Events include `supervisor.started`, `watcher.ready`,
`source.changed`, `bundle.started`, `bundle.failed`, `revision.ready`,
`deploy.started`, `deploy.coalesced`, `deploy.completed`, `deploy.failed`, and
`supervisor.stopped`. Compiler diagnostics go to stderr. Internal Node-to-Rust
control traffic uses bounded TSV frames (4096 bytes), a bounded 64-event channel,
and at most 4096 unacknowledged change timestamps. Invalid frames stop the session
and reap the child. Bundle manifests are generated by the trusted local watcher;
the supervisor validates the protocol and file presence/length. It does not
replace the native adapter's independent digest validation.

`revision.ready.bundleMs` is Rolldown's compiler duration.
`revision.ready.watcherEventToBundleMs` starts when the supervisor receives the
watcher's change event, which may occur after filesystem notification/debounce;
it is null on initial builds. It ends when the complete directory is published.
Only change sequences covered at build start are consumed by that revision.
This metric is **not file-edit-to-bundle time** and includes no native deployment.
The integration test independently clocks an actual file write through the
revision event and reports that wall time. Neither metric is app-edit-to-visible:
that requires a platform test observing the changed native UI after deployment.

## Verification

```sh
cargo test --manifest-path dev/Cargo.toml
cargo clippy --manifest-path dev/Cargo.toml --all-targets -- -D warnings
cargo build --manifest-path dev/Cargo.toml
node --test dev/tests/watch.test.mjs
node scripts/bundle.mjs
```

Tests use the installed real Rolldown watcher and temporary imported-source
fixtures. They cover import rebuilding, syntax-error recovery and last-good
retention, restart uniqueness, rapid-edit bundle/map agreement, deployment
serialization/coalescing, signal/command shutdown and malformed protocol cleanup.
No emulator, simulator, network endpoint, production dependency, or platform
deployment is required by these tests.
